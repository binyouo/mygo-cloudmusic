# Smart Fades 音频衔接

本地研究版本使用 [Music Assistant](https://github.com/music-assistant/server/tree/e16a4688130e9779dbce091c62ed8625c86ee64b/music_assistant/controllers/streams/smart_fades) 固定版本的候选规划器，原生 Go 播放器负责连续 PCM 播放和 DSP。上游源码、原始 SHA-256 与适配范围记录在 `scripts/smart_fades/SOURCE.json`。

## 分析与规划

- Beat This small0 与 MA 的 DBN 后处理检测拍点、下拍及三拍／四拍小节；FireRed AED 从实际音频识别人声活动；S-KEY 估计调性。逐字歌词仍用于显示和轻量分析提示，不替代神经人声分析。
- 分析整首解码音频的能量、频谱重心及低、低中、中、高四段 RMS，按 MA 的 1800 个时间箱保存。结果按 PCM 内容哈希缓存，文件变化或换音源不会错误复用。
- 使用 MA 的完整候选生成、冲突评分、救援方案和分频 EQ 规划：根据速度、拍号、调性、人声重叠及尾奏结构选择对拍混合、自然叠接、短淡化、高通过滤或回声收尾。清晰人声、结尾与前奏由上游保护策略决定；不再假定每对歌曲都能做同一种固定秒数淡化。
- MA 规划可能在保护条件允许时选择前奏入口或尾奏结束点。保留同专辑、重复曲目和播客的原始样本边界；模型未就绪、缺失节奏证据或规划失败时仍使用已有轻量分析／自然衔接。

## 连续播放

- 保留前后各最多 45 秒原速 PCM。独立解码器顺序定位尾部，避免 MP3 的近似字节 seek 导致分析与实际音频错位。
- Go 后台预渲染 MA 的分频增益时间表、Rubber Band 4.0.0 R3 保音高变速、过滤及回声效果。后曲保持原速，低频／中频／高频按测量结果交接，播放回调只复制准备好的 PCM。
- 同一个音频输出跨越切歌边界。按变速时间表积分映射原曲进度，并以实际输出长度校正端点；后曲的入口偏移同步进入歌词、进度和定位。续接解码器从头顺序读到接缝，避免 MP3 接续错位。
- 使用等功率或 MA 选择的自然包络，以及双声道联动的预感知控峰。归一化开／关各有独立增益包络。
- 队列变化、定位和被弃用的歌曲会取消对应预处理；新分析完成会替换早先轻量规划，旧结果不会覆盖新的曲目身份。

## 资源与构建

运行 `python3 scripts/setup-smart-fades.py` 准备独立 Python 3.12.14、固定版本推理依赖和四个校验过的模型文件；再运行 `python3 scripts/build-smart-fades-macos.py` 更新原应用包。运行时解释器、Torch、模型、Rubber Band 与 libsamplerate 都随包携带，不依赖用户的 Homebrew 或系统 Python，也不会在播放时下载模型。

重型分析一次只运行一个进程，最多使用两个 Torch 计算线程并降低进程优先级。只分析当前及待播曲目，单曲限制 8 秒至 20 分钟，推理有超时及取消。进程退出后释放模型；缓存最多保留 256 份分析，临时 PCM 在任务结束后清理。数据只在本机处理。

这次保持背景、动态封面、封面交互和本地歌词显示代码。验证包括 Go 回归检查、Python 候选规划检查和合成音频的离线分析／渲染／续接，不运行用户歌曲的播放测试，也不自动重启应用。
